Die Remindery-Methode

Ein Unternehmen, geführt von Agents.
Gesteuert von einem Menschen.

Produkt, Technik, Marketing, Finanzen, Recht: Jede Funktion hat ein Mandat, einen Takt und ein Gedächtnis – die Arbeit machen KI-Agents. Ein Mensch trifft jede Entscheidung, auf die es ankommt. Fünf Apps in den Stores sind der Beweis. Worum es eigentlich geht, ist das Betriebsmodell dahinter.

Die These

Die meisten Unternehmen ergänzen ihr Organigramm um KI.
Wir haben das Organigramm für KI gezeichnet.

Wenn Arbeit fast nichts mehr kostet, sind nicht mehr Hände knapp, sondern Urteil, Gedächtnis und Vertrauen. Also haben wir uns um genau diese drei organisiert – und alles andere den Agents gegeben.

Köpfe→Funktionen

Eine Abteilung ist keine Gruppe von Menschen mehr, sondern ein Mandat, ein Takt und eine Akte.

Machen→Entscheiden

Der Mensch macht nicht die Arbeit. Er trifft die Entscheidungen – und nur die.

Vertrauen→Beleg

Autonomie wird nicht verliehen, sondern verdient – gemessen am Urteil des Menschen.

Vorsicht→Mut

Wer nur aus Fehlern lernt, traut sich irgendwann nichts mehr. Bei uns muss jeden Monat ein mutigerer Schritt auf den Tisch.

Die Prinzipien

Sechs Prinzipien.
Alles andere ist Umsetzung.

01

Eine Funktion ist eine Akte, keine Person.

Das Gedächtnis eines Agents ist kein Chatverlauf, es ist gebaut. Jede Funktion führt eine Akte: Mandat, Rechte, Grenzen, offene Punkte, Lehren. Ein Lauf beginnt damit, sie zu lesen, und endet damit, zurückzuschreiben. So kann jeder Agent den Stuhl übernehmen – und nichts hängt davon ab, wer gestern darauf saß.

02

Können ist nicht Dürfen.

Skills bringen einem Agent bei, wie etwas geht. Ob er es darf, steht im Mandat – und wird von Code durchgesetzt, nicht von guten Absichten. Ein Agent, der weiß, wie man in den Store hochlädt, kann es trotzdem nicht.

03

Menschen treffen die Entscheidungen.

Drei Gates bleiben menschlich: was gebaut wird, was gut genug ist, was live geht. Alles dazwischen läuft allein – oft über Nacht.

04

Autonomie wird verdient.

Ein Schritt steigt erst auf, wenn das Urteil des Agents auf denselben Fällen immer wieder mit dem des Menschen übereinstimmt. Manche Schritte steigen nie: Geschmack ist nicht das, was automatisiert wird, sondern wofür.

05

Widerspruch kommt von außerhalb der Linie.

Ein Critic und ein Advocate prüfen jede Funktion – und berichten an den Menschen, nicht an die Funktion, die sie prüfen. Ein Agent, der seinesgleichen beaufsichtigt, erbt dessen blinde Flecken.

06

Lernen in drei Richtungen.

Jeden Monat: was verschärfen, was lockern, wo mutiger werden. Alle drei brauchen das Ja des Menschen. Sonst lernt ein Unternehmen nur aus seinen Narben – und traut sich langsam gar nichts mehr.

So funktioniert das Gedächtnis

Kein endloser Chatverlauf, sondern vier Schichten – jede wird genau dann geladen, wenn sie gebraucht wird. Das ist Context Engineering.

Control Plane

Ein Board.
Jeder Agent-Run startet hier.

Ein selbst gebautes Board ist das Cockpit. Der Gründer priorisiert per Drag & Drop, eine fertige Karte wird mit einem Klick zum Agent-Run. Jede Bewegung steht im Log.

▶ UmsetzenEine fertige Karte trägt ihren eigenen Prompt und ihr Arbeitsverzeichnis. Ein Klick startet einen Agent darauf.
Drei parallel, null KollisionenJeder Run belegt die Repos und Geräte, die er braucht. Ein zweiter Run im selben Repo stellt sich an – Überholen gibt es nicht.
Stopp bei „Go live?“Kein Run deployt einen Server, lädt in einen Store hoch oder veröffentlicht diese Website. Er schreibt die genauen Schritte auf und wartet.
🌙 FeierabendEin Knopf wartet auf laufende Jobs, startet einen Sicherungs-Agent, pusht alles – und fährt dann den Rechner herunter.

Automatisierungsgrad

Nicht alles soll allein laufen.

Manche Steps sollen bei „KI entwirft, Mensch entscheidet“ bleiben – Urteilskraft ist nicht das, was automatisiert wird, sondern das, wofür die Automatisierung da ist.

Leitplanken

Agents sind schnell.
Die Leitplanken sind die Methode.

Nichts geht von selbst live

Runs bereiten alles vor und halten bei „Go live?“ mit den genauen Schritten. Release ist eine menschliche Entscheidung, jedes Mal.

Eine Karte ist eine Änderung, kein Release

Änderungen sammeln sich auf main. Build, Versionsnummer und Store-Upload gibt es nur auf einen Release-Knopf.

Wächter auf dem Auslieferungszustand

Tests bewachen, was in den Store geht: Produktions-Schalter, Speicherseiten, Server-Stand. Schlägt einer an, wird das Bundle gar nicht erst gebaut.

Sign-off, das nicht verloren geht

Menschliches Urteil ist der Engpass – deshalb wird jeder Klick in einer Abnahme sofort gespeichert.

Zustand lebt in Dateien

Jeder unbeaufsichtigte Job hat eine Auftragsdatei mit Paketen und Haken. Bricht ein Run ab, macht der nächste dort weiter.

Context Engineering

Landkarten, Regeln und Lessons Learned liegen in versionierten Dateien, die jeder Agent liest – nicht im Kopf, nicht im Chatverlauf.
