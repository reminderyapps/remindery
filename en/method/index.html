The Remindery Method

A company run by agents.
Steered by one human.

Product, engineering, marketing, finance, legal: every function has a mandate, a rhythm and a memory – and AI agents do the work. One human owns every call that matters. Five apps in the stores are the proof. The operating model behind them is the point.

How does that work?
Let's look inside the engine room.
The thesis

Most companies add AI to their org chart.
We drew the org chart for AI.

When work costs almost nothing to do, hands are no longer the scarce resource. Judgment, memory and trust are. So we organised around those three – and gave everything else to agents.

Headcount→Functions

A department is no longer a group of people. It's a mandate, a rhythm and a file.

Doing→Deciding

The human doesn't do the work. The human owns the calls – and only those.

Trust→Evidence

Autonomy isn't granted. It's earned, measured against human judgment.

Caution→Courage

A company that only learns from its mistakes ends up afraid of everything. Ours has to put a bolder move on the table every month.

The principles

Six principles.
Everything else is implementation.

01

A function is a file, not a person.

An agent's memory isn't a chat history – it's engineered. Every function keeps a file: mandate, rights, limits, open items, lessons. A run starts by reading it and ends by writing back. So any agent can take the chair – and nothing depends on who sat there yesterday.

02

Can is not may.

Skills teach an agent how to do something. Whether it's allowed to is written in the mandate – and enforced by code, not by good intentions. An agent that knows how to upload to a store still can't.

03

Humans own the calls.

Three gates stay human: what gets built, what's good enough, what goes live. Everything in between runs on its own – often overnight.

04

Autonomy is earned.

A step moves up only when the agent's judgment has matched the human's on the same cases, again and again. Some steps never move: taste isn't what gets automated, it's what the automation is for.

05

Challenge comes from outside the line.

A critic and an advocate review every function – and report to the human, not to the function they review. An agent supervising its own kind inherits its blind spots.

06

Learn in three directions.

Every month: what to tighten, what to loosen, where to be bolder. All three need the human's yes. Otherwise a company only learns from its scars – and slowly stops daring anything.

The process

How work flows
through the company.

Six phases. Every step is an agent with a clear role, a versioned skill and a definition of done. Agents run on their own – the founder is on the loop, and in the loop at exactly three points: the concept, the sign-off and the Go.

01

Discovery

Research agents crunch store data, reviews and search demand. A critic and an advocate argue every idea – weak ones die by numbers.

founder decides

agents

Control plane

One board.
Every agent run starts here.

A self-built board is the cockpit. The founder prioritises by drag and drop; a card that is ready turns into an agent run with one click. Every move is logged.

▶ RunA ready card carries its own prompt and working directory. One click starts an agent on it.
Three in parallel, zero collisionsEach run claims the repos and devices it touches. A second run on the same repo queues – no overtaking.
Stops at “Go live?”No run deploys a server, uploads to a store or publishes this website. It writes down the exact steps and waits.

Guardrails

Agents are fast.
The guardrails are the method.

Nothing ships by itself

Runs prepare everything and stop at “Go live?” with the exact steps written out. Release is a human decision, every time.

A card is a change, not a release

Changes collect on main. Builds, version numbers and store uploads only happen on a release button.

Watchers on the shipping state

Tests that guard what goes to the store: production switches, memory page sizes, server version. Fail one and the bundle is never built.

Sign-off that can't get lost

Human judgment is the bottleneck, so every review click is saved the moment it happens.

State lives in files

Every unattended job has a brief with packages and checkboxes. If a run dies, the next one picks up where it stopped.

Context is engineered

Maps, rules and lessons live in versioned files every agent reads – not in someone's head, not in a chat history.
